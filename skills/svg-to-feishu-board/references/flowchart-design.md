## 先判断：要不要画流程图

流程图解决的是**"这件事按什么顺序发生、在哪里分岔、失败了走哪"**。当内容是并列的概念、职责划分、模块清单时，流程图不是合适形态——用表格或分区图。

一张图只讲**一条主线**。链路太长时按阶段拆多张（例：① 请求进入与校验 → ② 执行期消费 → ③ 收尾落库），而不是把三段塞进一张巨图。拆图的判据是"能否用一句话说清这张图讲什么"。

## 硬约束：菱形必须用 path，不能用 polygon

**这是本文最重要的一条，且与常见认知相反。** 虽然 `<polygon>` 被列为"可识别元素"，但实测它**总是**被降级为不可编辑图片。

对照实验（同一个菱形，同一份 SVG）：

| 写法 | 转换结果 | 可编辑 |
|---|---|---|
| `<polygon points="150,60 240,120 150,180 60,120">` | `svg` 节点 | ❌ 贴死图 |
| `<path d="M 450 60 L 540 120 L 450 180 L 360 120 Z">` | `composite_shape` | ✅ 可编辑 |

判断框是流程图的核心元素，降级成图片等于整张图失去二次编辑价值。所以：

```xml
<!-- 菱形判断框：正确写法 -->
<path d="M 402 455 L 520 411 L 638 455 L 520 499 Z"
      fill="#FEF3C7" stroke="#D97706" stroke-width="2"/>
```

`d` 的四个点顺序是：左 → 上 → 右 → 下，最后 `Z` 闭合。由 `(cx, cy)` 和半宽 `hw`、半高 `hh` 生成：
`M cx-hw cy  L cx cy-hh  L cx+hw cy  L cx cy+hh  Z`

**`<polygon>` 仍可用于小箭头三角**（约 14×15px）：这类节点降级成图片无害，既不需要编辑，也不影响观感。实测一张 101 节点的图里有 20 个这样的 image 节点，全部是箭头，可以接受。

投放后务必按下文回读确认：**不允许出现尺寸 > 40px 的 image 节点**。

## 反模式：信息卡片墙不是流程图

最容易犯的错误：画出一堆整齐的圆角矩形，每个方框里塞标题 + 三四行说明文字，方框之间用短箭头连起来，整体是规整的网格。**这是信息卡片墙，不是流程图**，会被明确判为不合格。

三条症状自检：

- 方框里塞了多行说明文字 → 方框内只应有 1 行短标签（≤14 字），解释性内容移到边标签或图外注记。
- 所有节点尺寸一致、排列成规整网格 → 流程图应当是**自由布局**，节点大小随内容变化，主干与分支明显不对称。
- 全程只有矩形、没有菱形 → 没有判断点的"流程"通常说明你画的是结构而非流程。

正确的流程图看起来是"不规整"的：主干贯穿、分支向两侧甩出、失败出口拐向边缘、少数节点明显更大。

## 骨架：主干竖直，分支横向甩出

- **主干竖直向下**，所有主干节点共享同一条中轴线（例：`cx = 520`）。读图方向单一，不需要来回找。
- **分支从菱形横向甩出**，左右两侧各自向下延伸，不要让分支重新汇回主干中轴（除非真的汇合）。
- **失败/异常出口一律甩到最外侧**，用红色系，与主干保持视觉距离。
- 允许留白不均。为了让某个复杂分支展开，主干可以在该处拉长间距。

典型竖版比例：`viewBox="0 0 1300 1400"`（单主线 + 2~3 处分支）。分支多时加宽到 1560，不要压缩节点。

## 五种节点形状及其语义

| 语义 | 形状 | 写法 | 建议配色（Pale 板） |
|---|---|---|---|
| 起点 / 终点 | 圆角矩形（大 `rx`） | `<rect rx="26" ry="26">` | `#DBEAFE` / 边 `#2563EB` |
| 处理步骤 | 圆角矩形 | `<rect rx="8" ry="8">` | `#FFFFFF` / 边 `#94A3B8` |
| 判断 | 菱形 | `<path d="M…Z">` | `#FEF3C7` / 边 `#D97706` |
| 失败 / 异常出口 | 圆角矩形 | `<rect rx="8" ry="8">` | `#FEE2E2` / 边 `#DC2626` |
| 分组 / 阶段 | 虚线大矩形 | `<rect stroke-dasharray="6 4" fill="none">` | 边 `#CBD5E1` |

形状承担语义，颜色只做强化。不要用同一形状靠颜色区分判断和处理——缩略图下辨识不出。

## 判断菱形与分流

菱形内只写**一个可判真假的短问题**，不写陈述句：

- ✅ `回合 ID 一致?` / `本 Pod 命中?` / `全部结果到齐?`
- ❌ `校验回合 ID 是否一致并决定后续走向`

每个菱形**必须有 ≥2 条带标签的出边**，标签写在线的旁边（不是线上）：

```xml
<text x="560" y="452" font-size="13" fill="#059669">是</text>
<text x="330" y="452" font-size="13" fill="#DC2626">否</text>
```

连续校验链（多个菱形串联、任一失败即出局）是很自然的流程图形态：菱形沿主干竖直排列，每个的"否"分支都横向甩到同一侧的失败出口。这种"四道校验链"结构比把校验塞进一个方框清晰得多。

## 连线与箭头

- **只用正交折线**：`<line>` 直连或 `<polyline>` 走水平/垂直折点。禁止斜线，禁止曲线。
- **`<line>` / `<polyline>` / `<path>` 会转成 `connector` 可编辑连线**，这是期望结果。
- 箭头单独画小三角，紧贴目标节点边缘：

```xml
<line x1="520" y1="160" x2="520" y2="192" stroke="#94A3B8" stroke-width="2"/>
<polygon points="520,197 515,188 525,188" fill="#94A3B8"/>
```

- 箭头三角尺寸约 10×9，`fill` 与线同色。
- 循环回路（如轮询重试）用 `<polyline>` 绕到节点侧面再回去，避免穿过其他节点。回路线可用 `stroke-dasharray="5 4"` 区分于主流程。

## 边标签：让每条线都能读出来

流程图的信息密度主要靠边标签，不是靠方框里堆字。每条非显然的边都应有标签，说明"在什么条件下走这条路"。

- 标签字号 12~13，比节点标题小一号。
- 颜色跟随语义：正常路径 `#475569`，成功 `#059669`，失败 `#DC2626`。
- 标签放在线的**外侧**，不要压在线上或与其他文字重叠。
- 竖直线的标签放线右侧 `x + 8`；水平线的标签放线上方 `y - 6`。

## 失败出口与注记

- 失败出口节点写清**结果**而非过程：`返回 not_running`、`403 无权访问`，而不是"处理失败"。
- 需要解释设计意图或标注已知问题时，用图外注记：右侧留白处画一个浅色小方块 + 文字，用细虚线指向相关节点。注记文字可以长一些（这是唯一允许多行文字的地方），但要与主流程视觉分离。
- 注记适合承载"这里曾经有个 bug""这两端不同源"这类不属于流程本身的信息。

## 尺寸与间距基准

在 1300 宽的竖版画布上（可等比缩放）：

| 元素 | 尺寸 |
|---|---|
| 主干节点 | 宽 240~360，高 52~66 |
| 双行节点 | 高 88~92 |
| 菱形 | 半宽 118~175，半高 44~46 |
| 主干竖直间距 | 节点边到边 30~40 |
| 阶段之间 | 60~80 |
| 节点标题字号 | 15~16（`font-weight="600"`） |
| 节点副标签 | 13 |
| 边标签 | 12~13 |

节点宽度按文字长度给足余量：CJK 约 1em/字、拉丁约 0.6em，再加左右各 16 内边距。宽度不足时画板会自动换行并压掉排版。

## 字符安全

实测在飞书画板中的表现：

- ✅ 正常：`①②③④`、`≠`、`′`、`→`、`⚠`
- ❌ 渲染成豆腐块：`✓`（U+2713）、`✕`（U+2715）
- ❌ 全角空格 U+3000 会导致间距异常，用普通空格

需要表达对错时用文字「是 / 否」「成功 / 失败」或用颜色，不要用对勾叉号。

另外：画板对 `transform="rotate(...)"` 的文字支持差，实测出现乱码。**所有文字一律水平**，包括竖直连线旁的标签。

## 投放后必须云端回读

本地 PNG 预览正常不代表云端正常。投放后按 `lark-whiteboard` skill 导出原始节点结构核对：

```
导出画板 raw 节点 → 统计 type 分布
```

三项判据：

1. **无大尺寸降级**：所有 `image` 节点尺寸都 ≤ 40px（只应是箭头三角）。出现大 image 说明有形状被降级，通常就是误用了 `<polygon>`。
2. **`composite_shape` 数量 = 矩形数 + 菱形数**（含背景矩形与虚线分组框）。少了就是有形状没被识别。
3. **`connector` 数量 ≈ 连线数**。文字节点数与 `<text>` 数一致。

实测参考（三张真实流程图）：节点 101 / 128 / 106，`composite_shape` 19 / 24 / 20，`connector` 20 / 26 / 12，大尺寸降级 0 / 0 / 0。

注：`--output-type preview` 导出 PNG 可能报 `expected image/png … got text/plain`（服务端问题）。此时改用 `--output-type svg` 导出再本地渲染核对内容。

## 检查清单

- [ ] 所有菱形用 `<path d="M…Z">`，无 `<polygon>` 画的判断框。
- [ ] `<polygon>` 仅用于 ≤15px 的箭头三角。
- [ ] 方框内文字 ≤ 1 行短标签，解释性内容在边标签或图外注记。
- [ ] 节点尺寸不统一、布局不是规整网格（不是卡片墙）。
- [ ] 每个菱形有 ≥2 条带标签出边。
- [ ] 连线全部正交，无斜线无曲线。
- [ ] 无 `✓` `✕` 字符，无旋转文字。
- [ ] 云端回读：大尺寸 image = 0，`composite_shape` 数对得上。
