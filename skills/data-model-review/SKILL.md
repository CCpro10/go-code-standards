# 数据模型与数据流转 Review

开始审查前读取 [完整专项规则](references/review-rules.md)，以该文档为审查依据。

优先检查长期对象与 Single Source of Truth。目标是以最少的必要数据概念、明确的所有权和生命周期表达完整业务流程；不能将结构体少或代码短直接视为设计更好。

## 执行

1. 明确审查范围：用户指定的提交、分支或文件优先；否则优先审暂存区。暂存区为空时审工作区与未跟踪的相关源文件；需要分支比较时先确认实际基准分支，用 merge-base 对比，不假设一定存在 `master`。说明采用的范围。
2. 沿必要的上下游追踪数据主链路：产生、解析、传递、修改、转换、消费与持久化。不能仅凭结构体定义下结论。
3. 优先识别跨阶段的 Request、Context、Task、Result、管理器和共享对象。逐字段确认来源、初始化阶段、读写者、所有者、最后使用位置与有效范围，判断是否保存了过期或临时状态。
4. 对关键业务事实确定唯一权威来源。区分可变副本、派生值、不可变快照、缓存和边界模型，查明生成、同步、失效与一致性约束。
5. 检查冗余复制、包装、转换、中间容器和状态缓存，再检查 IDL、数据库、常量和局部变量。综合兼容性、事务、查询性能、迁移成本与模块边界判断必要性。
6. 仅对有读写位置与流转证据的问题提出最小改进。不要机械拆 Context、合并边界模型或消除必要快照。只进行 Review，不修改代码。

## 输出

- 核心数据流转概览：来源、关键容器、转换与修改、最终消费者。
- 长期对象结论：跨阶段对象、字段有效期、临时状态与可收缩生命周期。
- 单一事实来源结论：权威来源、可变副本、同步依赖及合理重复表示。
- 具体问题：`[P1/P2/P3] 标题`，包含文件/行号及字段、设计缺陷、上下游读写证据、影响、最小修改建议与权衡。P1 为实际一致性、数据、兼容或明显性能风险；P2 为明确的重复事实来源、冗余长期状态或流转；P3 为有实际收益的小规模优化。
- 总体结论：长期容器与字段生命周期是否合理，核心事实来源是否明确，数据流转是否直接清晰。没有充分依据的问题时明确说明，不强行提出建议。

这是数据设计专项审查，不做通用命名或格式检查，不报告与当前修改无关的历史问题。
