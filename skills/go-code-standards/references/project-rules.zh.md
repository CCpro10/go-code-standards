# Go 表达规范（最高优先级）

本文件是中文权威规则；英文版本保持语义同步。只检查局部表达与 Go 约定。

- 命名准确表达真实职责、对象、动作与结果，优先较短但无歧义的名称。允许 Req、Resp、Config、Ctx 等惯用缩写，同一 package 保持一致。
- slice/array/list 使用具体元素业务含义的复数，如 userIDs、orders、skillRefs；map 使用 key2value，如 userID2user。泛泛的 list、items、data、mapping 不足以表达语义。
- 包内非 API 函数、方法和结构体必须小写开头。同 package 跨文件调用无需导出；接口契约要求的公开方法除外。
- 重要导出函数在前，其他导出函数其次，私有函数最后。不要为排序而无必要导出。
- 函数应有有用注释；复杂函数解释关键步骤、条件和业务边界。注释面向过程，例如“先解析高级创作标题，未得到时使用灵感创作标题”，不只写抽象概括。
- 导出结构体应详细说明含义、用途和边界，字段注释解释含义、来源、单位和限制。
- 变量尽量在失败点之后、首次使用前声明；失败返回显式空结构体或 nil。大结构体用 keyed composite literal 集中构造，避免先造空对象再逐字段补齐。
- 业务状态与协议值使用有语义且带注释的常量，避免裸字符串；常量是否重复定义归抽象审查。
- 参数、字段和逻辑阶段合理换行，禁止为压缩行数堆在同一行。package 命名简短有意义。
- 指针使用 code.byted.org/lang/gg/gptr 的 gptr.Of；数字需要明确指针类型时写 gptr.Of[int64](...) 等，不手写指针 helper。
- 拆文件和移动目录只提出建议，未获用户明确授权不执行。
- 先遵守本文件，再使用通用 Go 风格参考，再遵守不冲突的项目约定；用户当前明确要求优先。

数据模型、函数类型/变量、薄包装、流程编排、契约兜底和故障分别交给对应专项，不在这里重复报告。
